# バージョン運用ルール

## バージョン形式

開発中は `X.Y.Z-alpha.N` を使用します。製品版の完成条件を満たすまではα版を継続します。

## ベース番号の変更基準

| 変更内容 | ベース番号 |
| --- | --- |
| 小規模な修正・改善 | `0.1.1` |
| 大きな機能追加・仕様変更 | `0.2.0` |
| 製品版として安定し、完成条件を満たした段階 | `1.0.0` |

変更の規模と成熟度を確認して判断し、機能追加のたびに機械的に番号を上げない。

## α版の連番ルール

- `alpha.N` は更新ごとに1ずつ増やす。
- ベース番号が変わっても連番をリセットしない。
- 例：`0.1.1-alpha.94` → `0.2.0-alpha.95`
- バージョン表記は常に `X.Y.Z-alpha.N` とする。
- 製品版の完成条件を満たすまではα版を継続する。

## 製品版への移行条件

少なくとも、主要機能の実機統合試験、重大不具合の解消、データ移行・復旧の確認、セキュリティ確認、Windows配布物の検証、READMEと変更履歴の整備を完了し、安定運用できると判断できた段階で `1.0.0` へ移行する。CI成功だけを製品版完成の根拠にしない。

## 現在

現在のバージョン：`0.2.0-alpha.74`

`0.2.0` は、コメントビューア・動画ライブラリ・BGM・音声読み上げ・自動化・リモート操作／監査・放送監視など、複数の主要機能群が揃った開発段階を示します。これは安定版を意味せず、実機統合試験と録画機能などの未完了項目が残るため、引き続きα版です。

## 自動更新チャンネル

Windows Setup版ではalpha.yml／beta.yml／latest.ymlを使い分けます。beta版のリリースにはalpha向け、製品版にはbeta・alpha向けの更新ファイルも用意することで昇格に対応します。安定版を開発版へ自動変更することや、バージョンのダウングレードはしません。Portable版は現時点で自動インストール非対応です。

## バージョン更新履歴

アプリのサイドバー「バージョン更新履歴」から、各GitHub Releaseのタグ、公開日時、リリースノートを読み込みます。リリース時は変更点を正確に記載してください。過去版のリリースノートが存在しない場合、そのバージョンの追加機能や修正を推測せず、GitHub上の詳細を確認できるようにします。

## α67：更新履歴の記録と自動公開

新しいバージョンを公開する際は、`CHANGELOG.md` の先頭に `## X.Y.Z-alpha.N` 形式で見出しを作り、追加・改善・変更・修正を箇条書きで記録します。GitHub Releaseの公開処理はこの版の記録を読み込み、リリース本文に掲載します。アプリにも同梱され、GitHub APIが使えない環境でも確認できます。公開未確認の版を「公開済み」として扱わないよう区別します。

## α68：登録配信者監視の改善

監視処理は最大3件の同時確認で、利用者が設定した30〜300秒の確認間隔を処理完了後に適用します。Windows通知は任意に有効化でき、初期状態はOFFです。アプリを終了したりPCがスリープ中になった場合は監視・通知を行いません。

## α69：番組作成・引用再生の安全性

番組作成は本人のログインと明示確認を必須とし、重複作成防止記録を保存します。動画時間の補完は開始時刻を推測しません。動画リクエスト自動再生は初期OFFです。

## α70：自動アンケート・引用再生の安全性

APIから得た動画時間と引用動画IDを一致照合し、再生開始時刻が確認できない場合は投票を開始しません。ニコニコ動画情報取得APIのactionTrackIdを13桁ミリ秒形式に変更しました。アプリの再起動後は以前の引用再生時刻を信用せず、誤った自動スキップを回避します。

## α71：アンケートの開始時刻と動画尺の照合

引用再生の開始時刻を保持するのは、アプリ自身で開始した同一番組・同一動画の情報に限ります。動画尺が後から取得できた場合でも、時刻が不明または期限切れならアンケートを実行しません。自動取得には60秒間隔の再試行制限を設け、手動再取得は利用者の操作に限り許可します。

## α72：引用再生連動アンケート

自動アンケートは初期OFF。ユーザーがONに設定した場合だけ、アプリ内で引用再生を開始した動画に連動します。動画ID・番組ID・開始時刻を照合して重複を避け、「停止」操作で連動設定も解除します。

## α73：自動アンケート・放送開始時のリクエスト再生修正

自動アンケートのON設定を保存時に維持し、再生直後のニコニコ側状態反映の遅延を最大3回確認します。自動リクエストは新しい番組の終了時刻で候補を判定します。ニコニコ実配信での動作確認は引き続き必要です。

## α74：放送開始自動引用とアンケートの回帰テスト

放送開始時に使用する番組ID・リクエスト候補を固定し、認証と現在の引用状態を直前に検証します。自動アンケートの開始準備を排他し、ユーザーがOFFにした後の遅延実行を抑止します。IPCブリッジの公開漏れもCIで検出します。Windows実機・実配信検証は引き続き必要です。
