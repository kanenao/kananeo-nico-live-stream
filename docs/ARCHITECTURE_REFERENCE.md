# NicoLive Helper Standalone を参考にした設計方針

## 参考プロジェクトのシステム

参考先の [kanenao/nicolivehelper-standalone](https://github.com/kanenao/nicolivehelper-standalone) は、現在の kananeo nico live stream とは異なる「拡張機能移植型」のElectronアプリです。

- Electronのメイン画面で、New NicoLive Helper由来のHTML / JavaScriptを読み込みます。
- preloadでWebExtensions互換の `browser.*` APIと、アプリ専用の `stsen.*` APIを提供します。
- メインロジックは `NicoLiveHelper`、リクエストは `NicoLiveRequest`、ストックは `NicoLiveStock` として分離されています。
- リクエスト一覧とストック一覧は別のキューで、リクエスト優先、その後にストックを再生する仕組みです。
- 再生モードは手動・自動順次・自動ランダム。放送残り時間より長い動画を候補から外す運用もあります。
- 動画DB、マイリスト、あとで見る、再生履歴、ユーザー管理などを独立モジュールとして持ちます。
- リモートホストとリモートコントローラーを備え、Linuxヘッドレス運用も想定しています。

## 重要：再生方式が違う

参考先は、ニコニコ動画の視聴ページをアプリ内に開くのではなく、放送中の番組に対して引用再生APIを呼び出す方式です。

- 現在の引用再生状態：`GET /v1/tools/live/contents/{lv}/quotation`
- 最初の引用再生：`POST /v1/tools/live/contents/{lv}/quotation`
- 再生中の動画差し替え：`PATCH /v1/tools/live/contents/{lv}/quotation/contents`
- 引用再生停止：`DELETE /v1/tools/live/contents/{lv}/quotation`

この方式では、アプリの別ウィンドウで動画ページを再生するのではなく、ニコ生側の動画紹介・引用再生機能に動画を渡します。`src/quotation-api.js` にリクエスト生成と応答判定を独立させ、メインプロセスの専用Electronセッション経由でGET / POST / PATCH / DELETEを呼び出すIPCを接続しました。画面にはプレビューと引用再生を分けて配置し、引用再生前には確認ダイアログを出し、実行後に現在の引用再生状態を再取得します。実配信での統合試験はまだ行っていません。

## 動画ライブラリ（β16・β17）

- `src/video-library.js` が動画・再生履歴の正規化、検索、統合、編集を担当します。
- `src/main.js` は `app.getPath("userData")` 配下のJSONへ原子的に保存し、IPCの入力を検証します。
- Rendererはpreloadの限定APIだけを利用し、動画タイトル・タグ・メモの編集をメインプロセスへ依頼します。
- 編集は動画IDを基準に行い、既存の再生回数・登録日時・取り込み元・再生履歴は保持します。
- 取り込み元フィルターはローカル保存された `source` 値で絞り込み、API通信を追加しません。

## 一覧からの選択取り込み（β18）

- `app:video-library-list` は専用ログインセッションであとで見る／マイリスト／シリーズの一覧を取得し、保存せずRendererへ返します。
- Rendererは選択IDを保持し、チェックした動画だけを `app:video-library-import-selected` へ渡します。
- Main側は `prepareSelectedVideoEntries` で取り込み元を許可リストと照合し、動画ID・件数（最大1,000件）を再検証してから保存します。
- 取得上限はあとで見る／マイリスト／シリーズとも最大1,000件です。マイリストは最大2ページ（500件ずつ）、シリーズは応答の総件数を使って最大1,000件を要求します。実アカウントでのAPI応答確認はまだ必要です。

## ユーザー別コテハン・メモ（β19）

- `src/user-profiles.js` がユーザーID、コテハン、メモの正規化・重複排除・登録／更新／削除を担当します。
- データは既存のRendererローカル設定（`kananeo-beta2`）に保存し、ニコニコのアカウント情報や公開プロフィールは変更しません。
- コテハンはコメントビューアの表示名とコメント検索、コメントから受付した動画リクエストの登録者表示に反映します。
- 元のニコニコ表示名を受信できている場合は、コテハンの横に併記して見分けられるようにします。
- NGユーザー一覧とは分離し、表示名登録だけで受付許可／拒否の判定は変更しません。
- 1,000ユーザー上限、ユーザーID 128文字、コテハン80文字、メモ1,000文字で正規化します。

## コメント通信についての注意

ユーザーが指定したStandaloneの `app/src/main/main.js` / `comm.js` には、旧JSON WebSocket（`msg.nicovideo.jp#json`）方式が残っています。一方、New NicoLive Helper本家の現在の公開版はバージョン0.27で、2026年9月20日の更新履歴に「通信まわりをがっつりと変更」とあります。本家0.27のコードはNDGRのProtobufチャンクストリーム処理を含みます。

そのため、Standaloneの旧コメント通信部分をそのままコピーすることはしません。こちらのアプリで採用済みのNDGRコメント受信（nicomget）を維持し、コメント受信イベントを共通の配信セッション・リクエスト処理へ接続していきます。

## こちらのアプリで取り込む設計

画面デザインや拡張機能互換レイヤーをそのまま移植するのではなく、機能の分割と配信運用モデルを参考にします。

1. **配信セッションを中心にする**：放送ID、放送状態、放送主権限、コメント接続、引用再生状態、放送残り時間を一つのセッションとして扱う。
2. **リクエストとストックを分離する**：視聴者から来たリクエストと、運営が事前に用意したストックを別キューに保存する。
3. **再生スケジューラーを独立させる**：リクエスト優先、順次・ランダム、引用不可・再生済み除外、残り時間による候補選定をUIから分離する。
4. **引用再生をメインの再生手段にする**：実配信に動画を流す操作はメインプロセスから行い、公式動画ページを開く機能はプレビュー・確認用の補助にする。
5. **コメント処理を段階化する**：受信 → 正規化 → コマンド解析 → NG / 重複 / ユーザー別上限の検査 → リクエスト登録 → 結果応答。
6. **動画ライブラリを追加する**：動画情報、マイリスト、あとで見る、タグ検索、再生履歴をローカルDBで管理する。
7. **リモート運用は後段で追加する**：認証・TLS・権限・ネットワーク公開範囲を設計してから、ホスト／クライアント機能を追加する。

## 認証で引き継がない部分

参考Standaloneは外部Chrome / EdgeをCDPで起動し、Cookieを取得してElectronのデフォルトセッションへインポート・ファイル保存する構成です。こちらのアプリでは既存の専用Electron永続セッションを維持します。普段使いブラウザのCookieを抽出・転送しない設計を優先します。

## β16：動画ライブラリと再生履歴

`src/video-library.js` に動画情報の正規化、重複統合、検索、インポート、再生履歴を分離しました。ライブラリ本体はElectronのuserData配下の `video-library.json` に保存し、書き込みは一時ファイルからのrenameで置き換えます。既存ファイルが壊れている場合は読み込みエラーにして元ファイルを上書きしません。IPC操作は直列化し、Rendererにファイルシステムを公開しません。

`src/niconico-library-api.js` は、あとで見る、マイリスト、シリーズの一覧APIリクエスト生成と応答の正規化を担当します。ネットワークアクセスはメインプロセスのアプリ専用ログインセッションから行い、送信先を `nvapi.nicovideo.jp` に限定します。取り込んだ動画は重複IDで統合し、テキスト／JSONバックアップからも復元できます。JSONバックアップには動画一覧と再生履歴を含められます。

これらの一覧APIは非公式・非公開のWeb APIに依存するため、応答形式や認証条件が将来変わる可能性があります。単体テストは固定した応答例による形式テストであり、実アカウントでの取得成功を意味しません。マイリストは最大2ページ（500件ずつ）、シリーズは応答の総件数が取得できれば最大1,000件を1回で要求し、あとで見るは最大10ページ（1ページ100件）を取得する実装です。いずれも最大1,000件で止めます。

## β15：リクエスト受付結果の運営コメント返信

参考プロジェクトの `NicoLiveRequest.sendReply()` と `NicoLiveHelper.postCasterComment()` を参考に、受付／却下結果の運営コメント返信を追加しました。ニコ生の番組ページに含まれる `site.relive.csrfToken` をメインプロセスで取り出し、`PUT /unama/api/v3/programs/{lv}/broadcaster_comment` を呼び出します。トークンはRendererやログへ渡しません。

自動返信は初期OFFで、放送中の番組とアプリ専用ログインセッションを確認します。返信キューは直列処理し、5秒以上の送信間隔を設け、API権限不足やレート制限時には自動連投しません。返信テンプレートは受付／却下別に編集でき、動画ID・コメント番号・却下理由の置換に対応します。80文字を超える内容は切り詰めて送信し、通常視聴者コメントの投稿APIとは分けています。

送信APIの形式は公開実装例も照合しましたが、ニコニコ側の非公開・変更され得る仕様であるため、実アカウント／実配信での成功確認は未実施です。単体テスト成功を実送信の保証とは扱いません。

## β14：コメントリクエスト受付ポリシー

コメントからの動画リクエスト受付処理を `src/request-policy.js` に分離し、メインプロセスで判定するIPCを追加しました。NGユーザー・NGワード、リクエストとストックの重複、受付処理中の重複、全体200件、ユーザー別未再生上限を一つのポリシーで判定します。完了・スキップ・却下済みは上限に含めません。判定モジュールは単体テストで検証します。受付結果の自動コメント返信は、コメント送信APIとレート制限の確認が済むまで実装対象を分けています。

## β13：参考先の再生モードを反映

NicoLive Helper Standaloneにある「手動・自動順次・自動ランダム」の再生モードをこちらのUIにも追加しました。手動モードでは引用再生の自動次動画を強制OFFにし、次動画ボタンによる明示操作だけを許可します。自動順次・自動ランダムでは、従来のリクエスト優先・ストック代替の選定を維持します。コメント通信と認証は参考先の旧方式へ戻さず、NDGR Protobuf受信とアプリ専用Electronセッションを維持します。

## β12：引用再生の自動次動画

参考先の `playVideo()` が動画時間＋自動再生間隔で次動画タイマーを設定する方式を参考に、引用再生側にも予定時刻タイマーを追加しました。動画開始時刻・動画時間・待機時間をローカル設定へ保存し、起動時はニコ生の引用再生状態と動画IDを照合して復元します。予定時刻になったら、切替直前にもう一度ニコ生側の引用再生状態を取得します。引用再生が既に停止している場合、動画IDが変わっている場合、動画時間が未登録の場合、開始時刻が分からない場合は自動切替しません。

この方式は終了イベントを直接受信するものではなく、登録動画時間に基づくタイマーです。実配信でのAPI応答遅延、動画尺と実再生時間のずれ、放送側の広告・待機等は未検証です。実アカウント試験を経てから常用してください。
